# 注册角色定制（v1.3.0）

首次注册可选择肤色 5 种、发型 5 种、发色 6 种、上装 4 种、外套色 6 种、裤装色 5 种和配饰 5 种。预览即时变化，随机搭配同步所有控件和颜色按钮；小屏幕使用可滚动注册卡片。登录恢复账号外观，不重新选择。目前没有注册后的换装接口。

`shared/appearance.ts` 是选项与校验的唯一来源。Appearance 的七个字段 skin/hair/hairColor/outfit/coat/pants/accessory 都是选项范围内整数，拒绝额外字段、缺项、负数、非整数或任意材质 URL。默认值与之前经典角色一致，coat 可按旧会话颜色指定。所有外观使用同一碰撞、移动、攻击范围和战斗参数。

`client/avatars.ts` 同时生成预览和校园角色，增加短发、偏分、卷发、齐肩、发髻，以及卫衣帽兜、学院夹克配色、衬衫衣领、眼镜、帽子、围巾和背包。所有网格和材质由项目程序生成，不加载外部模型或纹理。`client/appearance.ts` 仅在表单展示或选择变化时渲染预览，隐藏时释放模型，复用预览渲染器，避免每次切换账号标签增加 WebGL 上下文。

注册协议保留原 color 字段兼容旧客户端，可增加 appearance。缺省 appearance 按 color 生成经典造型；提供时严格校验，保存后 Player.color 跟随 appearance.coat。登录和 resume 不能提交 appearance 修改存档。服务器显式构造 Player 并广播已保存的外观，依然只通过私有确认返回用户名。快照复制外观对象，防止内部调用方通过快照修改运行状态。

SQLite 版本 3 新增可空 appearance_json。新账号注册写入七项选项，旧账号迁移先留空；成功认证且房间有位置后再用经典默认和原会话 color 初始化一次。之后 color 不覆盖已保存外观。位置、战绩更新不会修改外观；原密码、令牌、显示名字和更新时间在迁移阶段保持。损坏的已保存 JSON 会报错，不静默覆盖用户造型。迁移与备份步骤见 [账号规则](accounts.md) 和 [部署说明](deployment.md)。

新增选项时保留旧整数编号，优先追加；删除或重排已有编号需要显式数据迁移。增加字段时升级协议兼容、旧数据默认和迁移步骤，同时更新模型、表单、README 与测试。外观与战斗尺寸变化分开处理，改变头顶高度须保持生命条和状态可见。

`tests/appearance.test.ts` 覆盖校验、独立存档、版本 2 升级、原字段保留、登录 / 令牌 / 重启保存及真实连接同步；`tests/e2e/appearance.spec.ts` 覆盖三维预览、随机搭配、模型实际配置、多页同步、退出与刷新恢复、小屏注册。
