# 共享汽车（v1.5.0）

西南角新增一个游戏内共享停车区，放置四辆可驾驶汽车。这是为游戏增加的停车设施，不宣称为实际校园停车场的测绘复原。

## 玩家操作

1. 在地图搜索“停车区”“停车场”或“汽车”，定位“西南角共享停车区”，可规划步行路线或空降过去。
2. 地图点选车旁位置时建议先放大，避免小地图像素对应数米的偏差。走到空车 4.5 米内，按 R 或点击“上车”。每辆车一次只能由一名玩家驾驶，已有驾驶员的车不可抢占。
3. W / 上箭头前进，S / 下箭头倒车，A / 左箭头和 D / 右箭头转向；空格刹车。车辆有加速、减速和速度相关的转向，原地不能旋转。
4. 按 R 或点击“停车并下车”，车辆立即停下，服务器选择车旁安全落脚点。车辆留在当时的位置，其他玩家可以继续驾驶。若周围没有安全落脚点，挪动车辆后再试。

最快前进为 15 米/秒（54 km/h），倒车为 5 米/秒（18 km/h）；Shift 不增加车速。车辆会被建筑、水域、边界、其他车辆及行人阻挡，不造成撞人伤害。车内不能出拳、格挡、闪避、空降或回到起点，也不参与拳击受伤，需先下车。导航仍为步行路线，未提供车辆路线或自动驾驶；动态车辆可能挡住步行路线，需要绕行。

失焦、打开阻止操控的界面、输入超时会刹车。退出、刷新或断线后释放车位并停车，恢复账号时站在车旁；异常断网按 Socket.IO 心跳超时释放，期间车辆输入租约超时即自动刹停。车辆不会因驾驶员断线继续无人行驶。

## 保存范围

车的位置、方向、速度及驾驶员状态由服务器房间维护，向所有页面广播；后加入者看到同一辆车停在相同位置。下车保存玩家落脚位置，账号原密码、外观、击倒和倒地记录保留。

车辆状态属于当前房间，不写入玩家 SQLite。服务器重启后四辆车回到停车区且无人占用，玩家仍恢复自己的存档位置；若存档位置落在重置车辆内部，会选择安全落点。无车辆购买、个人所有权或跨重启车辆存档。

## 开发与协议

`shared/vehicles.ts` 是固定车辆配置、输入校验、碰撞、动力学和上下车距离的共用来源。停车区中心为 (-635, 542)，四个车位中心分别为 (-635, 530/538/546/554)，入口朝西接西侧道路。

- `vehicle` 接受 `{seq, kind:'enter', vehicleId}` 或 `{seq, kind:'exit'}`，必须有递增整数序号。服务端限制频率、检测距离、互斥占用和忙碌动作，再返回 `{ok:true}` 或 `{ok:false,error}`。
- `drive` 只接受 `{seq, throttle, steer, brake}`，油门与转向在 [-1,1]，brake 为布尔值。拒绝额外坐标、速度、驾驶员和伤害字段；只有当前驾驶员输入能驱动车辆。
- 服务器以 20 Hz 模拟，动力学分为不超过 20 毫秒的子步；对建筑使用旋转矩形分离轴检测，对水域和边界检查车身采样点，动态车辆采用保守间距，行人采用扩展车身范围。
- 停驶车辆也阻挡步行，客户端同步同样的占位判断；车辆驾驶采用服务器状态与客户端平滑插值，不让客户端上传位置。
- `Snapshot.vehicles` 包含公开车辆状态，`Player.vehicleId` 指向当前车辆。使用公开 playerId 表示驾驶员，不广播用户名或令牌。
- `client/vehicles.ts` 使用自制几何体和材质绘制四辆车、停车位和标牌，驾驶/车轮动画复用已有实例。车辆不加入固定地图数据库碰撞，避免影响静态路径生成。

`tests/vehicles.test.ts` 检查命令校验、停车点、刹车、倒车、转向、建筑/边界/行人碰撞、安全下车，以及真实 Socket.IO 互斥占用、输入权限、闲置停车、交接和断线释放。`tests/e2e/vehicles.spec.ts` 用两个真实浏览器操作搜索、驾驶与交接，并生成停车和驾驶截图。所有测试使用独立或内存数据库。
