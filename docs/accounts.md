# 账号、登录用户名与公开显示名字

## 注册与登录

账号分为两个名字：

| 字段 | 规则 | 可见范围 |
| --- | --- | --- |
| 登录用户名 `username` | 自己指定，3–32 个字符，允许字母、汉字、数字和 `_ . -`；规范化全角字符、去除首尾空白，英文字母不区分大小写 | 账号本人登录界面与服务器，不向其他玩家广播 |
| 显示名字 `displayName` | 三组固定候选字各选一字，检查不合适的子串；不能与自己的规范化登录用户名相同 | 角色头顶、自己的 HUD 与公开游戏状态 |

登录用户名必须唯一，数据库唯一约束拒绝同时提交的重复注册。显示名字允许重复，角色仍由稳定的账号 ID 区分，不会共享位置和记录。显示名字不能用于替代登录用户名登录。

首次点击“首次注册”，填写登录用户名，从候选字选择显示名字，设置密码并定制角色，实时预览肤色、发型、发色、服装、外套、裤装和配饰。候选字和屏蔽词由前后端共同读取 `data/name-policy.json`，↻ 按钮可更换组合。私有用户名格式规则位于 `shared/usernames.ts`，不应用公开名字的选字与屏蔽词限制。

密码为 6–128 个字符。以后只用登录用户名和密码登录，不需要重新选择显示名字。同一账号同时只能一个页面在线；需先退出或关闭原页面再登录其他页面。刷新会自动恢复，关闭标签页后通常需再次登录。没有自助改名、账号删除或密码找回功能。

## 隐私与会话

公开 `Player.name` 只保存显示名字。服务器不把账号对象直接展开成玩家对象；`world` 快照、角色模型、聊天气泡、拳击事件和其他玩家能看到的界面都不包含登录用户名、密码或令牌。

登录 / 恢复成功时，用户名和随机令牌通过该连接的私有确认返回本人，不广播给房间。浏览器 `sessionStorage` 保存 `{token, username, displayName, color}`，不保存密码。令牌有效期 24 小时；使用密码重新登录会换发令牌。密码只存储随机盐和 scrypt 哈希，服务器保存的是令牌 SHA-256 哈希。

## 存档

游戏持久化内容包括七项角色外观、位置 `x / z`、击倒数与倒地数；账号 ID、用户名、显示名字和认证字段属于必要账号信息。

正常退出和断线立即保存，在线位置约每秒保存，回到起点和空降立即保存，击倒时双方记录在同一事务中保存。SQLite 使用 WAL；正常停止服务会先保存再关闭，强制终止可能丢失最后一次保存之后的位置变化。更新场景后若存档位置处于障碍中，选择安全出生点，累计记录保留。

血量、体力、临时动作、朝向、复活保护和聊天不作长期存档。短暂断线 30 秒内保留当前血量；退出后重新登录或服务器重启后满血进入。

默认数据库为 `var/accounts.sqlite`；服务器配置的文件位于独立 shared 目录，通过 `ACCOUNT_DB` 指定。不同环境拥有各自数据库，源码同步和发布包不会自动合并或替换玩家存档。测试使用内存或临时数据库。

## 旧账号升级

数据库版本 2 保留原来的唯一 `accounts.name` 列，将其作为**私有登录用户名**，新增 `display_name` 列存储公开名字。

- 已有账号仍用原三字名字和原密码登录。
- ID、密码盐 / 哈希、令牌哈希 / 有效期、位置、击倒 / 倒地数和原更新时间全部保留。
- 为避免继续在头顶显示登录用户名，为旧账号分配另一个合法候选字显示名字；此后重新登录和重启保留新显示名字。
- 老浏览器的 `{token, name, color}` 会话可自动升级成新的分离结构，原令牌继续有效。
- 升级在一个数据库事务内完成，重复执行不会再次改变已合法且与用户名不同的显示名字。服务启动时同样执行兼容检查；后续选字规则变化使旧显示名字不再合法时会替换公开名字，用户名和存档不变。

可在完成构建、正常停服及备份后显式迁移已有数据库：

```bash
node dist-server/migrate-accounts.js /absolute/path/to/accounts.sqlite
```

工具必须提供已经存在的数据库路径，核对迁移前后原认证和游戏字段的内容指纹一致，只输出状态、版本和账号数量。不要在正式服务仍写入数据库时运行。运行中的备份使用 SQLite 在线备份或 `VACUUM INTO`，不能只复制主文件漏掉 WAL。

回退到账号分离之前的代码会恢复旧名字语义，也不支持新的自定义用户名，因此不适合作为保持本功能隐私规则的回退版本。迁移发布前保留备份，并优先使用兼容当前数据库版本的程序回退；恢复旧备份只能恢复到备份时刻的数据，不能用旧备份覆盖已继续产生的新记录。

## 外观升级（版本 3）

版本 3 添加可空的 `appearance_json` 列。新注册账号保存七项固定选项；登录和恢复只读取服务器存档，不能通过登录参数修改外观。旧账号迁移后该列为 NULL，首次成功认证进入时初始化经典造型，并采用原会话提供的外套颜色；此前没有保存外套颜色，无法恢复已丢失的颜色。初始化只执行一次。

迁移不改动原账号字段。迁移工具动态核对所有已有列，包含已保存的公开名字与外观；重复执行保持一致。正常停服并在服务器本机完成一致备份后运行迁移。版本 2 程序会拒绝版本 3 数据库，回退须使用兼容版本 3 的代码；已有新写入时不能覆盖成旧备份。外观选项与模型扩展规则见 [外观说明](appearance.md)。

`tests/appearance.test.ts` 验证严格选项校验、原字段保持、重复迁移、重启存档、广播与伪造参数拒绝；`tests/e2e/appearance.spec.ts` 验证真实模型、实时预览、双页面同步、退出登录、刷新和窄屏注册。

## 验证

`tests/accounts.test.ts` 检查用户名规范化、候选字过滤、并发用户名唯一性、同显示名不同账号、旧数据库迁移和重复迁移、认证字段保留、真实 Socket.IO 广播隐私、重连 / 重启，以及 128 人加入、第 129 人拒绝和空位释放。

`tests/e2e/accounts.spec.ts` 验证注册表单、公开名字重复、两页面隐私、密码验证和存档；`tests/e2e/legacy-accounts.spec.ts` 使用旧数据库与旧会话，验证原密码登录和显示名字分离。所有这些测试都使用独立数据库。

共享汽车不属于个人存档。驾驶时账号仍保存当前位置，下车保存安全落脚点；退出、断线和重启后不恢复驾驶席。车辆的房间状态、刷新与停放规则见 [车辆说明](vehicles.md)。

校车座位不写入账号存档；退出、刷新、断线时释放座位并存储安全下车位置。重新登录恢复步行状态。v1.7.0 没有账号结构迁移。
