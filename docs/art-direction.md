# 三维画面与材质开发（v1.4.0）

本项目采用明亮、温暖的风格化校园画面。建筑仍按资料整理的平面和体量组织；画面美化不意味着建筑已达到测绘或写实游戏资产的精度。当前为浏览器中的自制程序化资产，不依赖外部贴图、人物资源、字体下载或后期滤镜。

## 渲染与资源

- `client/art.ts` 生成确定性的低分辨率石材、草地和水纹 CanvasTexture；设置 sRGB、重复采样及各向异性。纹理只在场景初始化生成，不能放进逐帧循环。
- 天空使用渐变球，材质反射环境通过 PMREM 预过滤生成。画面采用 ACES 色调映射、暖色日光和冷色天空补光。天空渐变自身不参与 ACES，避免重复压缩色彩。
- `client/scene.ts` 使用颜色缓存共享建筑材质。玻璃材质降低粗糙度、增加环境反射；石材保持漫反射。水面复用一份纹理，只每帧移动 UV，不进行实时镜面渲染，也不改变水域碰撞。
- 植被使用固定种子的实例化树冠、花卉和茎。树冠由四簇构成，叶色有轻微变化；径向透明纹理提供贴地阴影。栽植检查道路、水域、建筑、球场和广场，不能随意增加阻挡道路的装饰。
- 建筑重复构件继续分区实例化，保持可裁剪的包围球；入口增加门、雨棚及分隔。不要为所有窗框使用高细分倒角，会显著增加校园总览的三角形数量。
- `client/avatars.ts` 的圆角身体、平滑头部、鼻子、耳朵、眉毛、衣服缝线、鞋底和鞋带与注册预览共用。七项外观编号保持兼容；修改模型不得改变服务器攻击距离、移动速度和碰撞规则。
- 注册预览按需绘制，复用 renderer；丢弃旧模型时释放几何体和材质。PMREM 的中间纹理在生成后释放，最终环境纹理随场景存活。

## 验证和维护

执行 `npm run build`、`npm test` 和 `npm run test:e2e`；视觉调整后运行 `node scripts/capture-art.mjs`。后者自行启动 3016 的内存数据库隔离服务，结束时关闭服务，生成校园鸟瞰、学术环、水岸、会堂与玩家画面，收集浏览器和 WebGL 控制台错误及各视角渲染计数。

截图位于 `reports/screenshots/art-*.png`，指标见 `reports/art-verification.json`。渲染三角形包含阴影等渲染通道，不能直接等同静态模型面数；也不能用计数代替帧率。更高品质资产或后处理须先测量目标设备与多人场景，不承诺所有设备相同帧率。场景验证视角和全校总览必须保持可用。
